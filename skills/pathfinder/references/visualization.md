## 1. 什么时候可视化、选什么形式

原则：**先问"用户脑中需要同时追踪什么"，再选形式**。能用一个三行的缩进列表说清的，就不要做 HTML。

| 要表达的东西 | 最佳形式 | 怎么做 |
|---|---|---|
| 层级/包含关系（X 由哪些部分组成） | 思维导图/树 | 小：聊天里用缩进树或 Mermaid `mindmap`；大：build_map.py |
| 先修/依赖关系（先学什么后学什么） | 依赖图 (DAG) | build_map.py 的依赖图视图 |
| 步骤、阶段、流水线、工作流 | 流程图/流水线 | 小：Mermaid `flowchart LR`；大：map.json 的 `stages` |
| 两三个东西的对比 | 表格 | Markdown 表格 |
| 随时间的演变、历史脉络 | 时间线 | Mermaid `timeline` 或简单 HTML |
| 动态过程、算法执行、因果机制 | 可交互 2D 动画 | `assets/templates/animation-2d.html` |
| 参数如何影响结果 | 带滑块的 2D 图 | 同上，重点放在滑块 |
| 空间结构（几何、分子、晶体、网络层、3D 函数曲面） | 可旋转 3D 场景 | `assets/templates/scene-3d.html` |
| 状态转换（状态机、生命周期） | 状态图 | Mermaid `stateDiagram-v2` |
| 决策（如果……就……） | 决策树 | Mermaid `flowchart TD` |

Mermaid 适合在聊天里快速出图（很多客户端会直接渲染）。节点文字含括号、引号等特殊字符时用双引号包起来：`A["f(x) 的导数"]`。

## 2. map.json schema

```json
{
  "topic": "傅里叶变换",
  "slug": "fourier-transform",
  "mode": "concept",
  "problem": "复杂的波形能否拆成简单波形的组合，从而单独分析和处理每个频率？",
  "core": "把信号拆成不同频率正弦波的配方表",
  "learner": "懂三角函数和基本积分，没学过信号处理",
  "updated": "2026-10-30",
  "nodes": [
    {
      "id": "sine",
      "label": "正弦波三要素",
      "parent": null,
      "prereqs": [],
      "priority": "core",
      "status": "known",
      "summary": "振幅、频率、相位完全决定一个正弦波。",
      "why": "傅里叶变换的输出就是每个频率的振幅和相位。",
      "analogy": "",
      "pitfalls": ["混淆角频率 ω 和频率 f：ω = 2πf"],
      "check": "两个频率相同、相位差 180° 的正弦波相加会怎样？",
      "resources": [],
      "source": "",
      "est": "10 分钟",
      "review": {"interval": 1, "next": "2026-10-31"}
    }
  ],
  "stages": [
    {
      "id": "s1",
      "label": "阶段 1：建立直觉",
      "goal": "能用自己的话解释频谱是什么",
      "nodes": ["sine", "superposition"],
      "deliverable": "画出方波的前三个频率分量",
      "decision": ""
    }
  ],
  "detours": ["一上来啃复数指数形式和积分推导——先看动画建立直觉更快"]
}
```

字段说明：
- **必需**：`topic`、`nodes`，每个节点的 `id`、`label`。其余都可选——只写有内容的字段。
- `parent`：在思维导图中的父节点 id；`null` 或省略表示直接挂在主题根节点下。用于表达"属于/组成"。
- `prereqs`：真正的前置节点 id 列表。用于依赖图和推导学习顺序。只放"不懂它就完全无法理解本节点"的前置。
- `priority`：`core`（必须懂）/ `important`（应该懂）/ `optional`（以后再说）。
- `status`：`todo` / `learning` / `mastered` / `known`（用户原本就会）/ `skip`。
- `source`：材料拆解时填页码，如 `"PPT 第 12-15 页"`。
- `stages`：可选。有它时，路线视图按阶段画流水线；没有时，按依赖关系自动分层生成路线。行动模式和领域模式应该写 `stages`。
- `detours`：弯路清单，会显示在地图顶部。

### focus（行动模式的一页纸作战图）

行动模式应写 `focus`，地图会多出一个"聚焦"视图并默认打开它。所有子字段都可选：

```json
"focus": {
  "goal": "用一个垂直领域的账号建立可变现的个人影响力",
  "success": "3 个月内稳定周更，并有 1 条以上内容带来咨询或成交",
  "formula": "变现 ≈ 精准受众 × 信任 × 变现匹配度",
  "factors": [
    { "name": "精准受众", "state": "0 粉，未开始", "bottleneck": true },
    { "name": "信任", "state": "无作品" },
    { "name": "变现匹配度", "state": "有专业技能可做咨询" }
  ],
  "bottleneck": "还没有任何作品接受市场检验，其他变量都无从谈起",
  "priority": "4 周内按固定格式发布 12 条内容",
  "essentials": ["选题 = 目标受众的具体问题", "开头 3 秒给出结果或冲突"],
  "not_doing": [{ "item": "研究相机和剪辑软件", "why": "手机足够，内容才是瓶颈", "until": "稳定周更 4 周后" }],
  "metrics": { "leading": "每周发布数", "outcome": "完播率、收藏率", "review": "每周日 15 分钟" },
  "stop_rule": "发满 20 条后收藏率仍低于同类账号平均，就换选题方向",
  "sources": [{ "name": "平台官方创作者中心", "tier": "官方", "why": "规则以此为准" }],
  "today": "列出目标受众最常问的 20 个问题"
}
```

`factors` 中标 `bottleneck: true` 的一项会被高亮。`not_doing` 也可以直接写字符串数组。

规模建议：概念模式 5-15 个节点，领域模式 15-40 个，超过 40 个时拆成子地图（每个分区一张）。

## 3. 用 build_map.py 生成知识地图

```bash
python <skill-dir>/scripts/build_map.py learning/<slug>/map.json          # 生成 learning/<slug>/map.html
python <skill-dir>/scripts/build_map.py learning/<slug>/map.json --open   # 生成并在浏览器打开
python <skill-dir>/scripts/build_map.py map.json -o 输出.html
```

脚本会校验 JSON（未知的 parent/prereq id、循环依赖会报错或警告），然后把数据嵌入 `assets/templates/knowledge-map.html`。生成的页面：
- **思维导图**：可折叠的树，颜色表示优先级，标记表示状态
- **依赖图**：分层有向图；点击节点会高亮它的全部前置链和后续节点
- **路线**：按阶段或依赖层级排列的流水线
- **聚焦**（有 `focus` 时）：一页纸作战图——本质公式（瓶颈高亮）、唯一重点、最小必要知识、不做清单、指标、信息源、今天就做
- **详情面板**：点击任意节点查看 summary / why / 类比 / 误区 / 检验问题 / 页码
- **进度**：用户可以在浏览器里改节点状态（存在浏览器本地），"导出进度"按钮会复制一段文字，用户可以粘贴回对话，你据此更新 map.json

完全离线，不依赖 CDN，支持深浅色。

第一次生成时用 `--open`；之后更新进度时只重新生成，不要每次都弹浏览器。

## 4. 定制 2D 动画与 3D 场景

知识地图解决"结构"，动画解决"机制"。当用户需要看到一个东西**怎么动、怎么变**时，制作专门的可视化。

### 起点模板

- `assets/templates/animation-2d.html`：Canvas 2D 动画框架。包含：播放/暂停/单步/重置、速度控制、参数滑块自动生成、分步讲解面板（每一步的文字与画面同步）、深浅色、高 DPI 适配。你只需要填 `CONFIG`（标题、参数、步骤）和 `draw()` 函数。
- `assets/templates/scene-3d.html`：Three.js 3D 场景框架（从 jsDelivr 加载，固定版本）。包含：轨道相机（拖拽旋转/滚轮缩放）、灯光、坐标轴网格、文字标签、分步讲解面板、参数滑块、CDN 加载失败时的提示。你只需要填 `CONFIG` 和 `buildScene()` / `update()`。

复制模板到 `learning/<slug>/visuals/<名字>.html`，然后修改。模板里有注释标明要改的地方。

### 好的讲解型动画

1. **一个动画只讲一件事**。"傅里叶变换的缠绕直觉"是一个动画，"整个傅里叶变换"不是。
2. **分步讲解与画面同步**：用 `steps` 把过程分成 3-7 步，每步有一句话说明此刻在发生什么、应该注意看哪里。用户可以单步前进。这比让动画自己跑完有用得多。
3. **让用户动手**：至少一个有意义的滑块，并在讲解里提示"试试把 ____ 调到 ____，观察 ____"。用户亲手发现规律，比看完动画记得牢。
4. **高亮关注点**：当前要看的元素用强调色，其余用低对比度。颜色要有含义且前后一致（同一个量始终同一个颜色）。
5. **标注**：坐标轴、关键量的数值实时显示。
6. **真实**：动画里的数学/物理要正确——用真实公式计算，而不是"看起来像"。

### 3D 的使用场景

只在空间结构本身是理解的关键时用 3D：几何体、向量空间与线性变换、曲面与梯度下降、分子结构、神经网络的层与张量形状、天体运动、电磁场。纯粹的层级或流程用 3D 只会更难看清。

## 5. 交付方式

根据所在环境选择，优先让用户**零操作**就能看到：

1. **本地 HTML（默认）**：保存到 `learning/<slug>/`，用 `--open` 或系统命令打开（Windows：`start "" 文件.html`；macOS：`open 文件.html`；Linux：`xdg-open 文件.html`）。告诉用户文件路径。
2. **环境提供内联可视化工具时**（例如能在对话旁渲染 HTML/SVG 的工具）：小型的、一次性的示意图和动画可以直接内联展示。
3. **环境提供 Artifact/页面发布工具时**：用户想在手机上看或分享给别人时，可以发布成页面。
4. **只有文本时**：Mermaid 代码块 + 缩进树，并把 HTML 文件保存好供用户之后打开。
