# 五种模式的产出模板

所有模式共享同一个底层逻辑：**本质 → 骨架 → 路径 → 深入 → 验证**。区别只在于"骨架"由什么构成。模板是起点而非格式枷锁——内容不需要的部分就删掉。

## 目录
1. 概念模式
2. 领域模式
3. 问题模式
4. 材料拆解模式
5. 行动模式
6. 混合与切换

---

## 1. 概念模式

适用：单个概念、原理、算法、理论。"什么是 X""X 怎么理解""X 和 Y 有什么区别"。

**骨架**：本质问题 → 支柱概念 → 前置知识

```
## 它要解决的问题
在 X 出现之前，人们面对的困境是……（具体场景）
X 的核心想法是……

## 一句话
X 就是 ______（用用户懂的话）。
类比：就像 ______（来自用户熟悉的领域）。

## 理解 X 需要的几块拼图
（地图：3-7 个支柱，标出用户已经会的、需要补的）

## 从你已知的出发
你已经懂 A，X 其实就是 A 在 ____ 情况下的推广/变体/反面。
```

然后按分层讲解逐个支柱推进。

**示例思路**（傅里叶变换，用户懂三角函数但没学过信号）：
- 本质问题：一个复杂的波形，能不能拆成简单波形的组合？拆开后就能单独处理每个频率（去噪、压缩、分析）。
- 类比：棱镜把白光分成彩虹；耳朵把和弦听成几个音。
- 支柱：正弦波三要素（已会）→ 波的叠加 → "用相关性测量含有多少某频率"（核心洞察）→ 频谱 → 离散版本 DFT/FFT（可选）。
- 弯路：一上来啃复数形式和积分公式；先看动画理解"缠绕"直觉要快得多。
- 可视化：2D 动画——拖动频率滑块，看信号缠绕在圆上的重心如何变化。

## 2. 领域模式

适用：一个学科、方向、技能树。"入门 X""系统学 X""X 领域都有什么"。

**骨架**：领域地图（分区）→ 学习路线（阶段）→ 里程碑

```
## 这个领域在研究/解决什么
（一段话：核心问题、它和相邻领域的边界）

## 全景地图
（3-6 个分区，每个分区 3-6 个关键概念；标出核心/重要/可选）

## 推荐路线
阶段 1：____（目标：能做到 ____）  约 __ 小时/周
阶段 2：____
阶段 3：____

## 每阶段的里程碑
完成阶段 1 的标志：能独立 ______（一个具体可检验的任务）

## 弯路警告
- 不需要先学完 ____ 再开始 ____
- ____ 是常见陷阱：看起来重要，其实初期可以跳过
```

要点：
- 里程碑必须是**能做出来的事**，而不是"了解了 X"。"能用 pandas 清洗一份真实的 CSV 并画出趋势图"比"掌握 pandas"有用得多。
- 尽早安排一个小型完整项目，让用户把零散知识串起来。学习路线的形状应是"浅浅过一遍全流程 → 再逐段加深"，而不是"把第一章学到完美再学第二章"。
- 在 map.json 里用 `stages` 表达阶段，pipeline 视图会把它画成流水线。

## 3. 问题模式

适用：一个具体的"为什么/怎么办"问题。"为什么天空是蓝的""为什么我的模型过拟合""为什么这个证明成立"。

**骨架**：问题拆解 → 需要的概念 → 推理链

```
## 先把问题说清楚
你真正在问的是：____（有时需要帮用户把模糊问题变精确）

## 回答它需要知道的几件事
1. ____（你可能已经知道）
2. ____（需要简单补一下）

## 推理链
因为 A → 所以 B → 再加上 C → 得出结论

## 一句话结论

## 延伸：由此可以解释的其他现象
```

要点：
- 先给结论的简短版本，再展开推理——用户有了预期，跟推理更容易。
- 如果问题建立在错误的前提上，温和地指出前提的问题，这往往比回答本身更有价值。
- 对于调试类问题（"为什么我的代码/模型/实验不行"），推理链就是排查链：列出可能原因，按"可能性 × 排查成本"排序，给出验证每个原因的最小实验。

## 4. 材料拆解模式

适用：用户给了课件、讲义、教材章节、论文。详细流程见 `materials.md`。

**骨架**：材料自身的逻辑结构 + 页码映射

```
## 这份材料在讲什么
（一段话：核心主题和它想让你学会的能力）

## 结构还原
第 1-8 页：____（引入/动机）
第 9-20 页：____（核心理论）
...

## 概念地图（附页码）

## 重难点
- 难点：____（第 x 页）——为什么难：____
- 隐含前置：课件默认你懂 ____，但没讲

## 学习建议
推荐顺序、哪些页可以略读、哪些必须精读
```

## 5. 行动模式

适用：用户想做成一件事。"我想做一个独立游戏""怎么准备雅思""我想做自媒体/电商""我想把这个工作流自动化""怎么装修房子"。

**先读 `focus.md`**。第一次回复用其中的"一页纸作战图"（本质公式 → 瓶颈 → 唯一重点 → 最小必要知识 → 不做清单 → 指标 → 今天就做），并写入 map.json 的 `focus` 字段。下面的关键路径模板用于用户要看完整路线时，或作为作战图之后的展开。

**骨架**：本质目标 → 关键路径 → 决策点 → 弯路

```
## 你真正想要的是什么
表面目标：____
本质目标：____（例如"做独立游戏"的本质可能是"做出一个能玩、能分享的作品"，而不是"成为引擎专家"）
成功的标志：____（具体、可检验）

## 关键路径（流水线）
阶段 1 ____ → 阶段 2 ____ → 阶段 3 ____
每阶段：目标 / 关键动作 / 产出物 / 需要的知识或资源

## 关键决策点
在 ____ 时你需要选择 A 或 B：
- 选 A 如果 ____
- 选 B 如果 ____
我的建议：____（基于你的情况）

## 最常见的弯路
1. ____（为什么人们会走、怎么避免）

## 今天就能做的第一步
（小于 1 小时、能产生可见结果的一个动作）
```

要点：
- 第一性原理在这里的意思是：从"要达成的结果"倒推必要条件，而不是照搬别人的流程。问自己：哪些步骤是必要的？哪些只是惯例？最小可行版本是什么？
- 用户需要的知识只在路径上"用到时"补充——在行动模式里，学习服务于做事，不要先上一大堆理论课。
- 风险和不确定性大的步骤往前放（尽早验证），容易的放后面。
- map.json 用 `stages` 表达流水线，每个 stage 的 `nodes` 列出该阶段要掌握的知识点，`decision` 字段放决策点。
- 涉及医疗、法律、财务等高风险决定时，给出框架和要问专业人士的问题，而不是替用户做决定。

---

## 6. 混合与切换

真实对话经常混合：用户在学一个领域时问了一个具体问题（领域 → 问题），或者在拆解课件时想深入某个概念（材料 → 概念）。处理方式：
- 临时切到新模式回答，回答完说明"这个概念在你的地图上的位置是 ____"，然后回到主线。
- 如果新问题足够大，把它作为新节点加入现有 map.json，而不是另开一张地图。
