# 材料拆解（课件、讲义、PDF、论文、笔记）

课件和讲义的问题不在于信息太少，而在于：结构是按"老师讲课的顺序"而不是"理解的顺序"组织的；大量隐含前置没有说明；重点和铺垫混在一起；图和公式脱离了讲解就很难看懂。拆解的目标是把材料重组成用户能高效学习的形式，同时始终保留回到原文的路径（页码）。

## 流程

### 1. 提取

```bash
python <skill-dir>/scripts/extract_material.py 课件.pptx -o learning/<slug>/source.md
python <skill-dir>/scripts/extract_material.py 课程资料文件夹/ -o learning/<slug>/source.md
```

输出的 Markdown 用 `## [第 N 页]` / `## [幻灯片 N] 标题` 分隔，pptx 的演讲者备注会单独标出（备注里常有老师真正想讲的东西）。

文本稀少的页面（脚本会标记 `⚠ 文本很少`）通常是图、公式截图或扫描件。如果你能直接查看文件内容（比如读取 PDF 页面图像或图片），就去看这些页面；否则告诉用户哪些页的信息可能缺失，请他截图发来。

材料很长时（>100 页），先读目录/每页标题建立结构，再按需细读，不要一次把全部内容塞进上下文。

### 2. 还原逻辑骨架

回答：
- 这份材料想让学生**学会做什么**？（从习题、例题、总结页反推最准确）
- 材料自身的章节结构是什么？每段在整体中起什么作用（动机/定义/定理/例子/应用/总结）？
- 哪些是核心，哪些是铺垫或拓展？

### 3. 建概念地图

把材料中的概念写入 map.json，每个节点的 `source` 填对应页码。注意：
- **按理解顺序而非材料顺序**排 prereqs。如果材料在第 20 页才定义一个第 5 页就用到的概念，指出来。
- **补上隐含前置**：课件默认学生懂但没讲的东西，作为节点加进来，`source` 写"课件未讲，需补充"，并评估用户是否已经会。
- 例题和习题也可以作为节点（priority 通常为 important），它们是检验理解的最好材料。

### 4. 标出重难点

- **重点**：被反复提及、有专门总结、出现在例题/习题中、老师在备注里强调的内容。
- **难点**：概念跳跃大的地方、公式推导省略了步骤的地方、反直觉的结论。
- **易错点**：相近概念、符号约定、适用条件。

### 5. 输出学习指南

```
## 这份材料讲什么（一段话）
## 结构还原（页码 → 作用）
## 概念地图（build_map.py 生成）
## 重难点（附页码和原因）
## 课件没讲但你需要知道的
## 学习建议：推荐顺序、精读/略读页、可以跳过的部分
## 自测题（基于材料，5-10 题，附页码答案线索）
```

然后进入正常的逐节点讲解。讲解时引用页码："这一点对应第 14 页的那张图，那张图在说……"。

## 考试导向

用户说要考试时：
- 找出考试范围和题型（问用户，或从材料中的习题推断）。
- 按"考查频率 × 用户薄弱程度"排序复习重点。
- 多出和材料中习题同类型的练习题，讲解解题思路而不只是答案。
- 生成一页速查表（公式、定义、易错点）。

## 多份材料

一门课的多份课件：先分别提取，再合并为一张领域地图，标注每个概念出自哪一讲。跨讲的依赖关系往往是理解整门课的关键，要特别标出。
